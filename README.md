# Easy Compare

**轻量化文件备份同步工具** — 基于 **Tauri 2 + Rust** 的桌面客户端：比对任意两个目录的文件差异，并以单向增量方式安全备份到目标目录（例如从笔记本备份到移动硬盘），之后可随时重新查看差异并更新备份。

界面为单窗口双栏：左栏固定源文件夹，右栏固定目标文件夹，中间为「状态」与「复制」两窄列（`= ≠ → ← ! ·` 表示状态与方向，复制列每行一个按钮）；树内目录可逐级折叠展开，左右两栏始终同步。

## 一、快速开始

### 环境要求

| 项 | 要求 | 本机实测 |
|---|---|---|
| Rust | 与 tauri 2.11.5 匹配（本机 1.89 实测；升级到 1.90+ 后可解锁 2.12.x） | 1.89.0 `x86_64-pc-windows-msvc` |
| Node.js | 18+ | 22.22.2 |
| 系统 | Windows 10/11（WebView2 运行时） | Windows |
| 构建工具 | MSVC Build Tools | 已具备 |

> **版本固定说明**：本机 Rust 为 1.89，而 `tauri 2.12.x` 的 MSRV 已升到 1.90（edition 2024）。因此 `Cargo.toml` 把 `tauri` 固定为 `=2.11.5`、`tauri-build` 为 `=2.6.3`，`package.json` 把 CLI 固定为 `2.11.5`，并在 `src-tauri/.cargo/config.toml` 启用 `incompatible-rust-versions = "fallback"`，让整棵传递依赖自动避开要求 Rust 1.90 的版本。**升级到 Rust 1.90+ 后可去掉这些固定**。
>
> **为何没有使用官方 dialog 插件**：`tauri-plugin-dialog` 当前版本要求 Rust ≥ 1.90。本项目改由 Rust 侧自行调用 Win32 API 实现盘符枚举与目录浏览，零额外依赖，且能直接展示卷标与可移动磁盘类型，更贴合「移动硬盘盘符变化」场景。若你的 Rust 已升级，把目录选择换成官方插件是等价替代。

### 安装与运行

```bash
cd E:\projects\easy-compare
npm install                 # 安装 @tauri-apps/cli
npm run dev                 # 开发模式（自动启动 Rust 侧）
npm run build               # 生成 NSIS / MSI 安装包到 src-tauri/target/release/bundle/
```

单独验证 Rust 核心：

```bash
cd src-tauri
cargo test                  # 六态判定、路径越界、安全约束等单元测试
cargo check                 # 编译检查
```

**只想看界面**（不需要 Rust 环境）：直接用浏览器打开 `src/index.html`，会自动进入「演示数据」模式，全部界面交互可独立验收。

## 三、已落地的需求口径

PRD v1.0 的 8 项决策全部按 Q1-D／Q2-A／Q3-A／Q4-A／Q5-A／Q6-A／Q7-A／Q8-A 实现。

### 六态状态机（判定顺序固定，先命中者生效）

| 序 | 状态 | 编码 | 默认动作 |
|---|---|---|---|
| 1 | 冲突 | 紫 / `!` | 阻断自动执行，须逐项选择「用源覆盖／保留目标／跳过」 |
| 2 | 仅源有 | 琥珀 / `→` | 新增复制到目标 |
| 3 | 仅目标有 | 灰 / `←` | 默认保留；仅镜像模式才移走 |
| 4 | 内容不同 | 红 / `≠` | 源 → 目标覆盖（目标较新时额外标 `←` 警示） |
| 5 | 已同步 | 绿 / `=` | 不参与操作 |
| 6 | 未比对 | 浅灰 / `·` | 不参与批量操作 |

每行同时具备**色条 + 文字标签 + 中间列符号**，不单靠颜色传达状态。目录节点不参与写入判定，只汇总子树差异计数，中间列固定显示 `·`。界面底部的图例条默认收起，只留一个 `i` 图标，点击后才展开六态说明。

### 三项不可回退的安全约束

1. **默认不删除**：`mirrorMode` 默认 `false`。开启需在预演对话框勾选并经二次确认，确认框会逐条列出待移除文件，并明确提示「镜像范围与勾选无关，处理目标端全部孤立项」；待删项移入目标盘 `.easy-compare/versions/<时间戳>/deleted/`，不直接抹除。
2. **覆盖前留旧版**：`keepOldVersions` 默认 `true`，旧文件按相对路径移入 `.easy-compare/versions/<时间戳>/replaced/`。写入采用「同目录临时文件 → 设置修改时间 → 原子替换」。
3. **路径与卷校验**：前端只传会话标识、相对路径与开关；任何绝对路径到磁盘的映射都在 Rust 侧完成，`safe_rel` 拒绝 `..`、绝对路径与盘符。会话记录目标卷序列号 + 卷标，**预演时、执行前、每写一项前**都会重新校验，不匹配即拒绝写入。

### 命令契约（15 条，对应 PRD 4.5 的 7 类能力）

| 命令 | 作用 |
|---|---|
| `validate_and_bind` | 校验可访问性、可写性、卷标识，创建/更新会话 |
| `rebind_target` | Q8 盘符变化后按卷标识识别同一卷；不匹配须显式强制重绑 |
| `compare` | 后台递归扫描，增量回传 `scan-progress`，六态比对，支持取消 |
| `cancel_scan` | 置取消标志 |
| `verify_hashes` | 仅对选中项计算 SHA-256 并更新状态（Q2，不触发全量重算） |
| `create_plan` | 生成预演计划，复算容量与空间，计划留在 Rust 侧只回传 id |
| `execute_backup` | 一次性令牌执行，逐项进度事件，单项失败不中断整批 |
| `refresh_after_backup` | 自动重新比对、刷新状态树 |
| `list_drives` / `browse_dirs` | 目录选择 |
| `list_sessions` / `active_session` / `delete_session` | 会话持久化（应用数据目录 `sessions.json`）；`active_session` 返回上次实际使用的会话，避免启动时取到最旧的一个 |
| `export_report` | 结果报告 JSON |
| `app_info` | 产品与路径信息 |

其余实现点：目录级联勾选含部分选中态、只看差异／状态筛选／搜索、**目录逐级折叠展开且左右两栏严格同步**、**虚拟滚动**、单侧目录标注方向、过滤规则（扩展名 / 通配符 / 目录名，工具条可编辑并随会话持久化）、深浅色、键盘导航与高对比度、Q7 显示距上次备份天数（不创建定时器）、符号链接跳过并计数、同名大小写冲突阻断、无基线时提示「本次未做冲突检测」。

### 双栏折叠与大树渲染

| 项 | 做法 |
|---|---|
| 折叠控件 | 不用带框按钮，只用一对细线拼成的 **＋ / －**（展开为 －，收起为 ＋），点击区 18×16 但视觉很轻，不抢文件名注意力；**左右两栏各一个、缩进位置一致**，所以任一栏都能折叠、两栏天然同步 |
| 总按钮 | 工具条新增一组「展开全部 / 收起全部」：收起后只保留顶层目录，便于逐层查看；无目录或已达边界时按钮置灰（`aria-disabled`） |
| 折叠触发 | 点按钮、点目录名、点该行空白处均可；键盘 `Enter`/`空格` 折叠，`←`/`→` 收起/展开 |
| 单行选中 | **单击任意一行即可选中**：文件行只选自身，目录行选整棵子树（折叠状态下同样生效，子项无需渲染）；行内显示「已选 N」徽标；再单击取消；空格键等效。双击目录行 = 折叠展开，不改动选中 |
| 复制列 | 状态列右侧新增「复制」列，**每行一个「复制→」按钮**：点它把该行（单文件或整棵折叠目录）置为当前选择并直接打开预演清单；无待写入项的行显示置灰的「—」。写入仍需预演后确认，**不存在绕过预演的写入路径** |
| 折叠后 | 行内保留「子树 N 处差异」摘要；搜索时自动展开命中目录 |
| 单侧目录 | 缺失侧只显示 `—`（不再铺满长段说明）；标签按方向显示「缺失 / 待新增 / 全部保留」 |
| 行底色 | **整行按状态填色**（已同步淡绿 / 需更新淡红 / 仅源有淡琥珀 / 仅目标有淡灰 / 冲突淡紫 / 未比对极浅灰），浅色与深色主题各有独立色值；悬停与选中用半透明遮罩叠加，不覆盖状态色 |
| 配色 | 浅色主题用较高饱和度的状态色（绿 `#0d8b47`、红 `#d62626`、琥珀 `#cc7a00`、紫 `#6b34d6`、主色 `#0d63c9`）；**深色主题改用中性黑灰为底色**（`#08090a` / `#111214` / `#1b1c1f`，无蓝调），状态色只出现在色条与文字标签上；两套主题的整行底色都做过饱和度校验 |
| 标题栏 | 关闭系统窗口装饰（`decorations: false`），改为自绘标题栏：左上角为**应用图标**（`src/icon.png`，由 `make_icon.py` 同步生成），右侧自绘最小化 / 最大化 / 关闭，整条为拖拽区 |
| 默认展开 | 只展开第一层目录；其余用折叠按钮或「展开全部」 |
| 大树渲染 | **虚拟滚动**：视图先算成扁平行列表，DOM 里只保留一屏多一点；行高固定 34px。16800 个文件时 DOM 仅 ~24 行 |
| 复杂度 | 一次后序遍历缓存每个节点的子树统计（状态计数、可选数、已选数、搜索命中），渲染/折叠/筛选均为 O(n) 遍历 + 常量级查询，不再每行重复遍历子树 |

实测（`node scripts/verify_perf.cjs`，120 目录 / 16800 文件）：首屏 13 ms、全部展开 120 ms、折叠单个目录 122 ms、切换只看差异 93 ms、搜索 94 ms。

### 本轮修复（评审后）

| 级别 | 问题 | 处理 |
|---|---|---|
| P0 | 基线只记录本次写入项，首次同步后双端修改会漏判冲突、源静默覆盖目标 | 执行后按**源端全量快照**重建基线：已同步项、成功写入项均入基线，失败项剔除；源端整体不可读时保留旧基线 |
| P0 | 扫描取消/中断仍产出「正常」结果，镜像模式会误删目标端文件 | `ScanSide`/`CompareResult` 新增 `aborted`；不完整比对禁止生成可执行计划并在界面告警 |
| P0 | 扫描失败后 `scanning` 不复位，之后所有比对被永久拒绝 | 无论成功、失败或任务 panic 都统一复位 |
| P1 | 「原子替换」实为先删后改名，存在文件缺失窗口 | 直接 `rename` 覆盖（Windows 等价于 `MoveFileEx(REPLACE_EXISTING)`） |
| P1 | `verify_hashes` 持全局锁在主线程算 SHA-256 | 改为 `spawn_blocking`，锁内只做状态读写 |
| P1 | 基线不校验卷标识，强制重绑后可能加载旧基线 | 卷标识不一致时忽略基线并提示原因 |
| P1 | 启动恢复的是排序后的第一个（最旧）会话 | 新增 `active_session` 命令与 `ui_state.json` 持久化 |
| P1 | 中途中断时已完成项也不写基线 | 只要 `succeeded > 0` 即写基线 |
| P1 | 过滤规则后端就绪但前端无入口 | 工具条新增「过滤规则」，三类规则可编辑、回显并随会话保存 |
| P1 | 单侧目录在双栏都显示为存在 | 目录节点 `hasL/hasR` 取自真实扫描结果，空目录不再退化成文件节点 |
| P1 | 失败项无重试入口 | 完成回执列出失败项并提供「重试失败项」 |

## 五、已知限制与待实测项（不预设数值结论）

以下沿用 PRD v1.0 的口径，属于**未经真机验证的工程假设**，不是可验证事实：

- **时间戳跨文件系统精度**：NTFS 与 exFAT 的修改时间粒度和时区语义可能不同。实现中 `MTIME_TOLERANCE_SECS = 2` 仅作为默认容差常量（`scanner.rs`），**未量化验证其正确性**。遇到疑似误判时，请切换到「SHA-256 精确校验」或用「校验选中项哈希」兜底。复制后会用 `FileTimes` 保持源文件的修改时间。
- **卷标识稳定性**：卷序列号在同一分区格式化前后会变化，部分 USB 桥接芯片上报方式也可能不同。盘符变化后客户端只在卷标识一致时自动重绑，否则要求用户明确确认。
- **基线存放**：优先写目标盘 `.easy-compare/baseline.json`，目标盘不可写时降级到应用数据目录并在界面提示；降级后冲突判定可能不完整。基线自带卷标识，与当前会话不一致时会被忽略并提示（宁可少判冲突，也不误判）。基线内容按执行后的源端全量快照重建，因此「本就已同步」的文件也参与后续冲突判定。
- **超长路径 / 目录联接**：符号链接与目录联接一律跳过并计数，不递归成环。`std::fs::canonicalize` 在 Windows 上返回的 `\\?\` 前缀在**存储与展示前会被剥掉**（`platform::strip_verbatim` / 前端 `prettyPath`），std 的读写 API 在使用时会自动按需加回，因此不影响长路径支持；旧版本已存盘带前缀的会话会在载入时自动迁移。
- **性能**：未做扫描/哈希的基准测试，不承诺扫描耗时与内存指标。渲染侧已用虚拟滚动 + 一次遍历预计算，16800 文件时首屏 13 ms、折叠/筛选 < 130 ms；但后端仍一次性把完整树序列化返回，几十万文件量级需改为分页/流式返回（未实现）。
- **平台**：首版以 Windows 为目标平台。非 Windows 分支仅提供可编译的降级实现，卷标识与盘符逻辑未适配。

## 六、事实与推测的区分

**可公开查证的事实**：Tauri 2 由系统 WebView 承载前端、Rust 编写应用核心、两者经 IPC 通信；Tauri v2 以基于 ACL 的权限、作用域与能力机制约束 WebView 可调用的资源；官方 dialog 插件的 MSRV 与权限标识。完整 MLA 出处见 `PRD-folder-diff-backup-v1.0.html` 第 6 节（位于设计工作区）。

**设计与工程约定**：本项目的六态模型、字段结构、命令划分、卷校验流程、版本目录布局、2 秒时间戳容差、各项安全约束，均为实现者提出的方案，非第三方事实，也未经本产品实测。
